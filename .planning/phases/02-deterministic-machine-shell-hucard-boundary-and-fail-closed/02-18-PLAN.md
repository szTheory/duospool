<objective>
Make the required-test inventory fail closed and calibrate the whole gate with the five named negative controls plus the timeout and cancelled producers, all judged by the real checkers or the live runner (FIX-04, RUN-02, FIX-05; D-58, D-72 pin resolution, D-77, D-80).

Purpose: a green gate that silently ran fewer tests, or accepted a wrong expectation, is worse than a red one. Each failure mode gets a control that is itself judged by the real checker, and the producible outcomes (guest_failure, timeout, cancelled) are shown produced by the live runner; skip is never produced and stays red in the ingest controls.
Output: inventory-check with both-direction pin rules, the inventory controls, the live-runner controls, the named-controls stage and one mutation.
</objective>

## Artifacts this phase produces (this plan's share)
- scripts/inventory-check CLI: `[--expect CODES] [--root DIR]`; codes INV_REQUIRED_MISSING, INV_UNLISTED_CASE, INV_PIN_UNRESOLVED, INV_NOT_REQUIRED, INV_PIN_BACKLINK, INV_CASE_FIELD, INV_REQUIRED_EMPTY, INV_BAD_LINE; marker `STATUS inventory ok`. Case schema (D-58 nine keys plus the tenth `request` key, D-79(a)): id kind fixture request expect meaning required control expect_outcome pins; id equals the file stem; pins is an array of ledger ids.
- Rules: REQUIRED parsed like ledger REQUIRED (comments and blanks skipped, ids [a-z][a-z0-9_]*, INV_BAD_LINE otherwise, INV_REQUIRED_EMPTY when no ids); a REQUIRED id without a case file is INV_REQUIRED_MISSING; a case with required true not in REQUIRED is INV_UNLISTED_CASE; every ledger entry with pinning_test TEST:ID names an existing case (INV_PIN_UNRESOLVED) that is required (INV_NOT_REQUIRED) whose pins array contains that ledger id (INV_PIN_BACKLINK); a case pins entry whose ledger pinning_test is not TEST:that-id is INV_PIN_BACKLINK too.
- Runner kinds budget_spin (steps with ds_run against a stop function that never fires and reports timeout when the budget is exhausted) and spin_forever (steps ds_advance forever; used only by the cancel-spin mini-root, never in the real inventory).
- conformance-run modes: `control DIR` (flatten DIR/tests/conformance/cases, run the live runner on that TSV, print its RESULT lines, then check DIR/EXPECT) and `control-signal DIR SIG` (start the same run under the supervise mode in the background, wait until it has started, send SIG, then check the results). DIR/EXPECT holds one pair `ID OUTCOME` per line; each pair is matched with awk as `$1 == "RESULT" && $2 == ID && $3 == OUTCOME` on the RESULT lines (never a whole-line match). A missing pair exits 1; an absent or empty EXPECT exits 2.
- Mini-root controls: tests/gate/inventory (removed-required, unlisted-case, pin-unresolved, pin-not-required, pin-backlink, case-missing-field, required-empty, ok-consistent), tests/gate/wrong-literal (EXPECT line `wrong_literal guest_failure`), tests/gate/timeout-budget (`budget_spin timeout`), tests/gate/cancel-spin (`spin cancelled`; the live runner is signalled with TERM).
- Named-controls stage prints NAMED_CONTROL NAME RED_OK for removed-required, missing-field, unlisted-fixture, wrong-literal and romlike-binary (the last drives the plan 04 planted-pce case and requires RIGHTSTEST planted-pce PASS plus the ROMLIKE_BINARY code), then for the two outcome producers timeout-budget and cancelled-spin (the ingest of each fabricated-or-live line must report OUTCOME_TIMEOUT and OUTCOME_CANCELLED respectively); any NOT_RED fails the stage; a missing control file is exit 2.
- Stages (new): inventory (static, registered before build per D-60), inventory-negatives, named-controls (registered after build and after conformance, D-85, because it drives the live ds_runner and reads nothing from a later stage or an earlier gate run). Selftest lines: mutation-inventory-required-missing and mutation-wrong-literal-compare (the comparison line in conformance-run control mode that matches the `ID OUTCOME` pair field-wise carries the comment token rule-field-match). Stage count after this plan: 42.
- SPDX (D-80): scripts/inventory-check and inventory-rules.awk carry the MIT OR Apache-2.0 two-line header; control case TOML carries a 0BSD header comment.
