<objective>
Add content identity: an in-house SHA-256 over the supplied bytes, recorded with the content size and declared format, verified against NIST vectors and against the host hashing tool (D-47, D-59 synthetic images, CONT-04).

Purpose: every later record, manifest and golden leans on this hash. An in-house implementation is only trustworthy when an independent tool agrees at the padding boundaries.
Output: sha256.c, boot hashing, the record's content table, synth recipes, runner emit and hash flags, the host-tool sweep, NIST and record-field cases.
</objective>
