<artifacts_produced>
## Artifacts this phase produces (this plan's share)
- Core API: ds_digest(instance, out32), ds_digest_stream(instance, sink, ctx) (the same bytes the digest hashes, for tests), ds_region_info(instance, index, tag, ptr, len) (test accessor over live storage), ds_profile_hash(profile, out32).
- Digest stream: prefix `duospool-state` followed by a NUL byte, serializer version u32 = 1, then regions framed tag u32 (four ASCII bytes), length u32, payload, little-endian, in fixed order with fixed tags PROF (profile hash), CONT (content sha256, size, size enum), POWR (policy id, seed, has_seed), TIME (u64), RAM8 (8192 bytes), MPRS (8 bytes), PSGN (u32), VDCP (u32): eight regions. One region table serves both the digest and ds_region_info.
- Profile identity hash: canonical stream with prefix `duospool-profile`, version, id, rev, for each of the 13 fields in table order name, status, value, bound_by, then the sorted unresolved_behaviours ids; labels excluded (identity is (id, rev) plus canonical resolved text, D-27). profile_fields.def gains the ledger id list per field (the ledger keys of r1; powerup_policy carries LED-PROF-0002 as a core constant because r1 omits it).
- Cases (all in REQUIRED, all ten keys): digest_stream_prefix (captures the stream with ds_digest_stream and checks prefix, NUL, version and the frame of each region in order with code that does not call ds_digest, then requires the SHA-256 of the captured stream to equal ds_digest), poweron_same_seed_same_digest, poweron_diff_seed_diff_digest, digest_region (flips one byte of live state per region reached through ds_region_info and requires the digest to change and the restored byte to restore it; assertions equal the region count, 8), nonmutation_digest (takes the digest of a live instance before and after every refuse-kind row of the matrix and requires equality), profile_hash_fields (each of the 13 fields flipped changes ds_profile_hash; label changes are not representable in the core).
- Toy control (D-85, plan 09 mechanism): tests/controls/drop-region holds two files, RULE (tag rule-drop-ram8-payload, file src/core/serial.c, an anchor that matches exactly one line of the live file, and the replacement that drops the single stream-writer call emitting the RAM8 payload while the region table still reports RAM8) and EXPECT (lists digest_region). The toy source is generated into build/ at control time by scripts/control-mutate and compiled with the live core; nothing under tests/controls is a copy of a src/core file. The plan 09 controls mode prints CONTROL drop-region RED_OK.
- SPDX (D-80): every new .c, .h and .def file carries the MIT OR Apache-2.0 two-line header; case TOML and the RULE file carry 0BSD.
