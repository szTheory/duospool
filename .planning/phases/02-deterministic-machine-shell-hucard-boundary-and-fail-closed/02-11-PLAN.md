<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host content bytes and declarations to ds_boot | untrusted, possibly guess-shaped |
| content bytes to runner output and CI logs | ROM-internal strings must not leave the process |
| emulator-style heuristics | content-based guessing is a correctness and rights hazard |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-02-20 | Tampering | host mutating its buffer after load (TOCTOU) | high | mitigate | ROM copied into the instance array at boot; boot_copy_in_isolated mutates the source buffer after boot and checks the read-back bank bytes are unchanged |
| T-02-21 | Information Disclosure | ROM-internal strings echoed to logs, records or CI output | high | mitigate | single emit function; redaction_synthetic_rom with run-time unique markers; redaction_seeded_leak_flagged proves the scanner can see a leak |
| T-02-22 | Tampering | content heuristics (byte-order, header, mapper guessing) changing behaviour on adversarial bytes | high | mitigate | noheur rows plus the heuristic-reverse toy shown red; refusals carry no diagnostic hint |
| T-02-23 | Tampering | refusal mutating caller memory or a live instance | high | mitigate | nonmutation_matrix byte comparison with guard canaries; a refusal writes only the result struct by construction; the digest upgrade lands in plan 13 |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | no package-manager installs in this plan |
</threat_model>
