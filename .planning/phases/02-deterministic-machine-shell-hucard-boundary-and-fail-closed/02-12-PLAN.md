Purpose: with no CPU in this phase, a stepping API that only counts would let a shared-state bug pass every determinism test. Evolving, seeded state is what gives the later liveness controls teeth, and the power-on policy is part of every recorded run.
Output: poweron.c, advance.c, the two seed refusals, eight cases with independently derived literals, and LED-PROF-0002. The canonical digest follows in plan 13 and the record in plan 14.
</objective>

## Artifacts this phase produces (this plan's share)
- splitmix64 (written in-house, unsigned arithmetic only): state += 0x9E3779B97F4A7C15; z = state; z = (z xor (z shift 30)) times 0xBF58476D1CE4E5B9; z = (z xor (z shift 27)) times 0x94D049BB133111EB; output z xor (z shift 31). Vectors for seed 0: 0xE220A8397B1DCDAF, 0x6E789E6AA1B965F4, 0x06C45D188009454F.
- Power-on (D-50, D-75): domain constants (64-bit, fixed, documented in poweron.c, not enum ordinals): ram8k 0x52414D384B5F5F5F, psg_noise 0x5053474E4F495345, vdc_phase 0x5644435048415345 (ASCII-packed names). For each domain: sub = the output of one splitmix64 step started from state (seed XOR DOMAIN_CONST); the domain stream is a splitmix64 generator whose initial state is sub; draws are successive 64-bit outputs written as little-endian bytes. ram8k draws 8192 bytes; psg_noise takes the low 32 bits of its first output (forced to 1 if zero); vdc_phase the low 32 bits of its first output. Zero policy: RAM zero, psg_noise 1, vdc_phase 0. MPR bytes (8) are a documented all-zero constant with an open ledger item for Phase 3. Policy names zero and seeded-prng-v1 (the v1 suffix freezes algorithm, derivation, domains and draw order).
- Request fields powerup_seed (u64) and has_seed; request grammar gains seed=N (the policy comes from bind.powerup_policy). New refusals appended with the next stable numbers: powerup_seed_required (21), powerup_seed_unexpected (22); new check powerup in boot_order.def directly after bindings (D-79(b)).
- ds_advance(instance, cycles): machine time adds cycles; psg_noise is an xorshift32 register (x xor x shift-left 13; x xor x shift-right 17; x xor x shift-left 5) stepped once per cycle; vdc_phase is a u32 adding cycles with wraparound; cycles above DS_ADVANCE_MAX = 1048576 per call is refused. ds_run(instance, budget, step, stop_fn, ctx) returns DS_RUN_STOPPED or DS_RUN_BUDGET (budget exhaustion is what the runner reports as timeout, D-57); a budget exactly consumed does not exceed it.
- Internal API in ds_poweron.h: stream init and draw functions per domain (test access), ds_poweron_apply (called by boot).
- Cases (all in REQUIRED, all ten keys): splitmix_seed0, poweron_zero, poweron_draw_order (pins LED-PROF-0002; the first 16 RAM bytes for seed 42 as spec literals derived independently), ref_seed_required, ref_seed_forbidden, advance_rules, run_budget, poweron_domain_independence; plus a new pair in the existing ref_precedence_table (a seed fault beats a later undeclared mapper).
- Ledger: LED-PROF-0002 (area PROF, assumed; statement: the power-on policy modelled as above; withheld list: any claim that guests do not depend on uninitialised memory, any hardware claim for placeholder state evolution (a fixed placeholder generator, not a hardware LFSR), any hardware claim for the MPR constant; pinning_test TEST:poweron_draw_order; revisit_phase 3; origin 02-CONTEXT D-50). Per D-85 the entry carries every schema key: id, statement, profile (pce-hucard-2btn), status, sources, evidence (empty array), disagreement (none), pinning_test, updated, assumption, revisit_phase, withheld, origin. It is listed in ledger/REQUIRED as exactly the line `LED-PROF-0002 02-CONTEXT D-50` (id, then the entry's origin text verbatim; ledger-check requires equality).
- SPDX (D-80): every new .c, .h and .def file carries the MIT OR Apache-2.0 two-line header; the ledger entry and case TOML carry 0BSD.
