<objective>
Complete the plain-HuCard mapper boundary: the size enum, 256K, 384K and 1M mirroring, unmapped banks, and an independent oracle proving the documented bank signatures (D-44, D-59, CONT-01).

Purpose: the three-emulator agreement on 384K is only trustworthy if the test expectation does not share code with the implementation. The oracle carries its own arithmetic and refuses to run when the ledger rule text it mirrors changes.
Output: ds_mapper.h and mapper.c, extended synth recipes, the oracle, banksig and unmapped cases, and LED-LOAD-0003 and LED-LOAD-0005. The wrong-mirror toy control, the size-refusal rows and LED-LOAD-0004 follow in plan 09.
</objective>

## Artifacts this phase produces (this plan's share)
- Core: mapper API ds_mapper_read(instance, bank, offset, out) returning DS_MAP_OK, DS_MAP_UNMAPPED (bank 0x80 and above, no value: Phase 3 owns it) or DS_MAP_BAD_OFFSET (offset 8192 and above); size enum DS_SIZE_256K, DS_SIZE_384K, DS_SIZE_1M stored in the instance instead of the raw size. ds_boot's supported_size check is exactly the three enum sizes (every other bank multiple, including 8192, is size_unsupported).
- Rule text (all assumed; the literal clauses the oracle guard matches): "256K file bank = b mod 32"; "384K file bank = b and 0x1F when b below 0x40, 0x20 + (b and 0x0F) when b is 0x40 or above"; "1M file bank = b"; "banks 0x80 and above are not ROM". The record keeps mapper plain and mapper_rule plain-v1.
- Fixture recipes: plain-256k, plain-384k, plain-1m, plus len:N from plan 07. Tag formula: first byte of file bank k is (k * 37 + 11) mod 256, last byte is (k * 91 + 5) mod 256; the LCG seed spec string is part of the recipe.

- Cases (all in REQUIRED): accept_256k_banksig, accept_384k_banksig (pins LED-LOAD-0003), accept_1m_banksig, accept_unmapped_banks (pins LED-LOAD-0005); every case carries all ten keys.
