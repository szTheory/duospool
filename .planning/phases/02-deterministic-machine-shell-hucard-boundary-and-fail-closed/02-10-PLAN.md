<objective>
Add the sanitizer stage inside the fast gate, prove it is alive, prove zero allocation on refusal rows, and make the one mode-scoped exclusion explicit and checked (D-41, D-46 SIZE_MAX row, D-55 sanitizer rules, D-78).

Purpose: a refusal that overruns a buffer or touches a bogus pointer is the failure mode this phase exists to prevent. A sanitizer stage that silently does nothing, or an exclusion that silently grows, would hide it.
Output: preset and stage sanitizers, canaries, ref_too_large_size_max, the allocation shim and its two cases, EXCLUDED_IN_MODE with its ingest assertions and controls.
</objective>

## Artifacts this phase produces (this plan's share)
- Preset `sanitize` (inherits the hidden base warning flags and does NOT carry -fwrapv, D-83; adds -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer, binaryDir build/sanitize). If the hidden base preset carries -fwrapv in the tree as found, move it into the gate, gate-gcc and gate-clang presets in this task (CMakePresets.json is in this task's files) so only the sanitize preset lacks it. Because -fwrapv is absent, UBSan reports signed overflow and over-wide signed shifts. Any UBSan finding in core code is a real defect: fix it with unsigned arithmetic or explicit casts (widen before shifting, do intended wraps on unsigned types); never add -fwrapv to the sanitize preset or suppress the report; stage `sanitizers` (after conformance); conformance-run mode sanitize (compiler: /usr/bin/clang on Darwin passed through CC, cc elsewhere; ASAN_OPTIONS detect_leaks=1 on Linux only; wall watchdog about 3x). CMake options DS_ALLOC_SHIM (ON for gate presets, OFF for sanitize) and ds_canary (built only when sanitizers are on).
- ds_canary modes heap (one byte past a small heap array), overflow (signed int addition that overflows, operands opaque to the optimizer) and shift (a signed left shift that overflows); the heap canary must be reported by AddressSanitizer and both the signed-overflow canary (INT_MAX plus a runtime value of 1 in a signed int) and the signed-left-shift canary (shift of a signed value into or past the sign bit) must be reported by UBSan as runtime error, each with a non-zero exit and its own message; the canary set is therefore heap, overflow and shift, and the planted signed overflow can only fire because the sanitize preset has no -fwrapv (D-83); otherwise conformance-run prints SANITIZER_DEAD NAME and exits 1.
- Cases (REQUIRED): ref_too_large_size_max (request ptr=dummy len=size_max, expect load.too_large; dummy pointer non-NULL, never dereferenced), alloc_shim_selfcheck (kind alloc_zero: calls the allocator once from the test and requires the counter to read 1), alloc_zero_matrix (kind alloc_zero: reads the shim counter around every refuse-kind row in the cases TSV and requires 0; assertions equal the number of rows run). Linux interposition of the shim is untested here; the nm check in plan 15 is the primary no-allocator proof (stated in the allocshim.c header).
- tests/conformance/EXCLUDED_IN_MODE: SPDX comment lines then rows `MODE ID`; initial rows `sanitize alloc_shim_selfcheck` and `sanitize alloc_zero_matrix`.
- Runner flag --exclude-ids FILE (omit those ids; RUNNER_DONE counts executed lines only). conformance-run sanitize derives the file from the sanitize rows and prints `EXCLUDED_IN_MODE sanitize ID` per excluded id.
- conformance-ingest options: `--mode NAME --excluded FILE [--gate-results FILE]`. Codes: EXCL_BAD_LINE, EXCL_NOT_REQUIRED (listed id not in REQUIRED), EXCL_NOT_PASS_IN_GATE (listed id lacks a pass RESULT in the gate-mode results; both the gate run and the sanitize run assert it), EXCL_RAN_IN_MODE (a listed id has a RESULT line in the mode it is excluded from); an unlisted REQUIRED id without a RESULT stays OUTCOME_MISSING_ARTIFACT (an unlisted exclusion fails). The sanitize mode requires build/gate/results.txt to exist (exit 2 otherwise).
- Controls tests/gate/excluded (mini-roots with results.txt, gate-results.txt, EXCLUDED_IN_MODE, REQUIRED, cases): excl-ok, excl-unlisted (OUTCOME_MISSING_ARTIFACT), excl-not-pass-in-gate, excl-not-required, excl-ran-in-mode, each EXPECT an exact code set. Stage `excluded-mode-controls` (run_controls). Selftest line mutation-excluded-gate-pass (delete the lines tagged rule-excl-gate-pass from a scratch copy of the ingest; the excl-not-pass-in-gate control must flip).
- Stage count after this plan: 31.
- SPDX (D-80): canary.c, allocshim.c and every new script carry the MIT OR Apache-2.0 two-line header; EXCLUDED_IN_MODE carries it as comment lines; case TOML 0BSD.
