## Artifacts this phase produces (this plan's share)
- tests/controls mechanism (D-85, toys track live source): each tests/controls/NAME holds exactly two files, RULE and EXPECT. RULE is line-based `key=value` text after `#` comment lines (SPDX 0BSD header) with four keys: `tag` (rule-NAME-..., the rule's identity), `file` (repository-relative path of one live core source), `anchor` (a literal substring, matched as a fixed string, never a regex) and `replace` (the text that takes the anchor's place). EXPECT lists case ids (one per line) that must come out guest_failure. `scripts/control-mutate RULE OUT [--root DIR]` (new, sh and awk, SPDX MIT OR Apache-2.0) counts the occurrences of the anchor in the live file; exactly one occurrence is replaced and the whole file is written to OUT; zero or more than one prints `CONTROL_ANCHOR_COUNT TAG n=N` and exits 2 (a harness error, never a pass). Generated toy sources go to build/PRESET/controls/NAME/ (never under tests/ or src/). CMake globs tests/controls/*/RULE with CONFIGURE_DEPENDS, reads each `file=` line with file(STRINGS), and defines a toy runner target per directory from the ds_core source list with that one file replaced by the generated path (marked GENERATED, so it need not exist at configure time); the private include directory still resolves the core headers.
- Selftest mutation-control-anchor (in scripts/check, one PASS line per rule found under tests/controls: `SELFTEST mutation-control-anchor NAME PASS`): for each RULE, copy the live source into a scratch root, break the anchor there (change its first character) and require control-mutate to exit 2 with n=0; then duplicate the anchor line and require exit 2 with n=2. A rule whose anchor still matches once after the break prints FAIL.
- conformance-run controls mode (runs after the matrix inside the conformance stage): for each tests/controls/NAME runs control-mutate on the live source (exit 2 propagates as a harness error), builds the toy target with `cmake --build --preset PRESET --target ds_toy_NAME`, then runs each toy runner against the same cases TSV, requires for every EXPECT id a RESULT line whose id and outcome fields are that id and guest_failure (awk field match, not a whole-line match) plus RUNNER_DONE; prints `CONTROL NAME RED_OK`, or `CONTROL NAME NOT_RED` (fails the stage), and exits 2 when an EXPECT file is absent or empty.
- Toy: tests/controls/wrong-mirror (RULE with tag rule-wrong-mirror-384k, file src/core/mapper.c, an anchor that is a literal substring of the one live line holding the 384K rule (chosen by the executor from plan 08's mapper.c and proven unique by control-mutate) and a replacement that makes the rule b and 0x3F; EXPECT lists accept_384k_banksig).
- Cases (REQUIRED): ref_size_8192 (len 8192, expect load.size_unsupported) and ref_size_512k (len 524288, expect load.size_unsupported, pins LED-LOAD-0004).
- Ledger: LED-LOAD-0004 (status open; disagreement lists MAME 0,1,2,3 repeated versus Beetle and Geargrafx banks 32 to 63 repeated for 512K and MAME special 192K versus modulo 24; the three sizes are refused by the supported-size rule (size_unsupported), and the statement notes that a 2 MiB image is refused by the 1 MiB cap (too_large, D-82), not by the size rule; pinning_test TEST:ref_size_512k; withheld any claim about a 512K, 768K or 192K card; origin 02-CONTEXT D-44). Per D-85 the entry carries every schema key: id, statement, profile (pce-hucard-2btn), status (open, so no assumption or revisit_phase is required), sources, evidence (empty array), disagreement, pinning_test, updated, withheld, origin. It is listed in ledger/REQUIRED as exactly the line `LED-LOAD-0004 02-CONTEXT D-44` (id, then the entry's origin text verbatim; ledger-check requires equality).
- SPDX (D-80): scripts/control-mutate and every new script and awk file carry the MIT OR Apache-2.0 two-line header; RULE files, the ledger entry and case TOML carry 0BSD.
