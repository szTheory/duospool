<objective>
Make fixtures fail closed: a manifest with one entry per emitted recipe and a gate that hashes the emitted bytes independently and compares (FIX-02, D-59, D-60).

Purpose: a green gate that used an undocumented image, a changed generator, or a recipe nobody listed is worse than a red one. The manifest coverage claim is made true by construction: the runner enumerates exactly the recipes it will emit, including the 21 sweep recipes.
Output: fixtures/manifest, scripts/fixture-check, the runner's --fixtures list, conformance-run fixtures mode, and the fixture controls with two mutations.
</objective>

## Artifacts this phase produces (this plan's share)
- Manifest files fixtures/manifest/ID.toml (0BSD SPDX header comment; ID equals the file stem; recipe name maps to ID by replacing each hyphen or colon with an underscore, for example plain-256k to plain_256k and len:513 to len_513). Keys: id, kind (synthetic, authored or exception), source (tests/conformance/synth.c), recipe (the generator spec string, including LCG constants, seed, tag formula and size), toolchain, size, sha256, licence (SPDX id from the allowlist 0BSD, MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, CC0-1.0), notices, redistribution (generated-not-committed or committed), meaning, verdict_source (spec-literal:LED-AREA-NNNN, guest-computed, or independent-script; the literal duospool-output is rejected).
- scripts/fixture-check CLI: `[--expect CODES] [--root DIR] [--partial] --used FILE` where FILE lines are NAME SIZE SHA256; `--partial` (passed only by a conformance-run fixtures --only run) disables FIX_STALE so a one-recipe used list is not read as a staleness verdict, and the real stage never passes it (D-85); codes FIX_MISSING_FIELD, FIX_UNKNOWN_KEY, FIX_UNLISTED, FIX_HASH_MISMATCH, FIX_SIZE_MISMATCH, FIX_BAD_VERDICT_SOURCE, FIX_BAD_LICENCE, FIX_BAD_ENUM, FIX_STALE (manifest entry never used), FIX_ID_FILENAME_MISMATCH; marker `STATUS fixtures ok`; an empty --used file is exit 2.
- Runner flag --fixtures: prints `NAME SIZE` for every recipe named by a fixture key in the cases TSV, implied by a len=N override that materialises bytes (a row with ptr=null, ptr=dummy or len=size_max materialises none), and named by the --sweep-lengths list (len:N), de-duplicated and sorted, one line each; it is produced by the same resolver the cases use, so the list cannot drift from what the runner emits.
- conformance-run fixtures mode: `sh scripts/conformance-run fixtures [--only NAME]` first performs the same two producing steps as the run mode (D-86; one shared function in the script): flatten tests/conformance/cases to build/gate/cases.tsv (END row required) and build incrementally with cmake --build --preset gate, so it never reads a stale binary or TSV; it then writes build/gate/fixtures.used (NAME SIZE SHA256 where SHA256 is computed by the host tool, sha256sum if present else shasum -a 256, chosen once, over `ds_runner --emit NAME`) for every line of `ds_runner --fixtures` (or only NAME, which also passes --partial) and runs fixture-check. The `fixtures` stage calls this mode without --only as its first step and then asserts that every manifest file has a matching line in build/gate/fixtures.used (D-85); it never reads a used file left by an earlier run.
- Manifest directory fixtures/manifest, exact counts (D-85): 1 file from Task 1 (plain_256k), 23 files from Task 2 (plain_384k, plain_1m and one len_N per each of the 21 sweep lengths listed in plan 07), then Task 3 adds exactly N_case files, where N_case equals the line count of `ds_runner --fixtures` minus 24 (at least 14 are expected: the distinct len=N overrides of the plan 09 and 11 refusal and precedence rows that materialise bytes, plus any extra fixture keys); the final count equals the line count of `ds_runner --fixtures`.
- Controls tests/gate/fixture (mini-roots): fix-missing-field (no notices key), fix-unlisted (a used.txt naming a fixture with no manifest file), hash-mismatch, size-mismatch, bad-verdict-source (the rejected literal), stale-entry, ok-listed.
- Stages (new): fixtures (after conformance), fixture-negatives. Selftest lines: mutation-fixture-missing-field, mutation-fixture-unlisted. Stage count after this plan: 39.
- SPDX (D-80): scripts/fixture-check and fixture-rules.awk carry the MIT OR Apache-2.0 two-line header; every manifest file and control TOML carries a 0BSD header comment (the extended licence-check scans fixtures/).
