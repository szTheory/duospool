## What the core does now (Task 1)

- **`lfo_applies`:** LF CTL != 0 and select 0 and select 1 both chON (D-219).
- **`lfo_f0`:** F0' = (F0 + $1000 + (w << s) - (16 << s)) & $FFF, with 0 read as 4096.
  - w is wave[1][0] while TRG = 1, else wave[1][widx[1]].
  - The shift is the single statement `uint32_t s = 2u * ((ctl & 3u) - 1u);`, which is the toy anchor.
- **`chan_period`:** while the LFO applies, select 0 steps at d x F0' and select 1 at d x F1e x FLFe. Select 1 is coupled only when TRG = 0.
- **`fold_lfo`:** catches select 0 up in closed form to the instant before the next select-1 step, then steps select 1. So a select-0 reload at the same instant reads the new word (the D-185 tie order).
- **Starts:** `chan_start` (key-on, DDA release, TRG release) reads `chan_period`, so a start under an active LFO uses the coupled period or F0'.
- **CTL change:** a CTL change on a running counter applies at its next reload, because the pending distance is never touched.
- **UNMODELLED retired:**
  - The R9 path no longer sets bit 6.
  - psg_effects.def keeps the bit defined, with a row comment that no write sets it since 05.1-01.
  - Two psg_lfo_trg rows expected it. They now expect R9 $7D to post effect 0 and R9 $FF to post LFO_RESET alone.
