### psg_fold bound arithmetic (d = 3 and 6)

- pf_invariant (psgkinds.c:631) refuses a running channel with r > 6 x 4096; 05.1-01 T1 changes the select-1 bound to d x (DS_PSG_COUPLED_REM_MAX / 6) = d x 1,048,576.
- d = 6: 6,291,456. d = 3: 3,145,728. Each equals the largest coupled period d x F1e x FLFe with F1e = 4096 (F = 0) and FLFe = 256 (FLF = 0).
- Between steps r never exceeds the current period. The step_end fold rebases to the step's last clock, which is at or after every processed event and write stamp. chan_start puts the next event at w - w mod d + period, so r is at most the period.
  - A pending coupled distance after a CTL change is still at most the coupled maximum.
  - So the widened bound holds with equality at the extreme, and the strict > keeps it accepted.
- pf_program's random R2, R3, R8 and R9 writes (register (r >> 16) % 10) can reach that extreme, not only the 109,056 the action cites, and the d-scaled bound covers it. psg_fold runs at d = 6 (plain-256k, default profile); the d factor keeps the rule right for a d = 3 instance.
- Select 0 under modulation stays at most d x 4096 (F0' in 1..4096), inside the unchanged bound. The fold offset bound holds: 600 + 6,291,456 = 6,292,056 < 2^23 (psg.c static assert).
- Restore rows: 12,289 and 3,145,729 are both 1 mod 3 (on the d = 3 grid at time 0). 12,289 <= 3,145,728 is accepted; 3,145,729 is the first grid point past the bound, refused by range only. p-rem1coupover = psg_grid_max(b, 6291456) + 6 is past the bound on the d = 6 grid. p-rem1over (about 24,580) and p-rem1coupled (at most 6,291,456) are accepted.
