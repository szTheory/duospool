1. `scripts/audit-history [REPO]`, with the SPDX header. Start from the tested RESEARCH script and make these changes:
   - (a) Keep `scan_blobs` as a function outside any `$( )` (the bash 3.2 `case` bug).
   - (b) The batch-check format must include `%(rest)`. Any non-blob, non-tree, non-commit, non-tag line (missing or unreadable) prints `UNREADABLE …`.
   - (c) Count NUL bytes by comparing `wc -c` before and after `tr -d '\000'`.
   - (d) Flags: `NUL-BYTES`, `ROM-SIZE-8K` (size at least 4096 and a multiple of 8192), `ROM-SIZE-HDR` (size mod 8192 is 512), `EXT` (pce, sgx, iso, cue, bin, rom, chd, sav, srm, zip, 7z, pem, key, case-insensitive), and `TEXT-PATTERN` (private-key headers, AKIA keys, gh*_ tokens, xox* tokens, `/Users/<name>/`, `/home/<name>/`, via `git grep -I -n -E` over `$(git rev-list --all)`).
   - (d2) Self-match safety (the scripts/audit-history file is itself in history). Write every TEXT-PATTERN so that its own source text cannot match it: each fixed prefix is followed directly by a bracket expression that the next source character (`[`) does not satisfy, for example a home-path pattern whose name part is a character class of letters, digits, dot, underscore and hyphen. Do not put a literal example token, key header or home path in a comment or string of the script.
   - (e) Read the allowlist `scripts/audit-history.allow`. Lines have the form `path<TAB>CHECK<TAB>reason`, with `#` comments. A hit is suppressed only when both its path and its CHECK match. For a ROM-SIZE allowance, the blob must also have zero NUL bytes, or the hit is still reported.
   - (f) Print each remaining hit as `<CHECK> <size|line> <path>`. Exit 1 if any hit remains, otherwise print `audit-history: clean` and exit 0. A git failure is exit 2.

2. `scripts/audit-history.allow`. It lives under scripts/, so licence-check requires its SPDX lines: lines 1 and 2 are `# SPDX-License-Identifier: MIT OR Apache-2.0` and `# SPDX-FileCopyrightText: Copyright (c) 2026 The DuoSpool Authors` (the `#` comment form the allowlist format already accepts), followed by a one-line `#` comment giving the format. Do not add any TEXT-PATTERN, EXT or NUL-BYTES entry. Those need the owner (Task 2).

3. `tests/audit/synthetic.sh`. It creates repositories under `mktemp -d`, removed by a trap, using `-c user.name=duospool-test -c user.email=test@example.invalid -c commit.gpgsign=false`. Cases:
   - `rom-blob`: an 8192-byte zero `x.pce`. Expect a non-zero exit and output containing NUL-BYTES, ROM-SIZE-8K and EXT.
   - `missing-object`: commit a file, then delete its loose object file under `.git/objects`. Expect a non-zero exit with UNREADABLE.
   - `home-path`: a text file containing a macOS home-directory path for a made-up user. Build the string at runtime from its parts (for example with printf), so the committed test script does not itself match the audit pattern. Expect TEXT-PATTERN.
   - `allowlisted-ok`: an allowlisted NUL-free 16384-byte text file. Expect clean.
   - `allowlisted-binary`: the same allowlisted path, but the content gains NUL bytes in a later commit. Expect NUL-BYTES or ROM-SIZE-8K to be reported.
   - `clean`: expect `audit-history: clean`.
   - `self-scan`: commit a byte-for-byte copy of `scripts/audit-history` (and nothing else) into a synthetic repository. Expect `audit-history: clean`, which proves the pattern literals do not match the script's own text.
   Print `AUDITTEST <case> PASS|FAIL`, and exit 1 on any FAIL.

4. Run `sh tests/audit/synthetic.sh`, which must pass. Then run `sh scripts/audit-history .` on the real repository, saving its output, and `gitleaks git --no-banner --redact -v .`, saving its summary. A non-clean real-repository result is expected here: it is the input to Task 2, not a task failure. Put both outputs verbatim in the SUMMARY draft for the checkpoint.

Commit the scripts and the allowlist. They are not added to scripts/check. Phase 2's FIX-05 builds the tree-level repository check.
