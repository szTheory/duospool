# Phase 4.1 - Validation Strategy

> Per-phase validation contract for the sprite scope that Phase 4 left at the D-180 cut. The Phase 4 contract is `04-VALIDATION.md` (complete for the background, interrupt, DMA, palette and dot-clock scope); this file holds the rows of the plans 04.1-01 to 04.1-03 (CONTEXT plans 04-12 to 04-14, former files 04-14 to 04-16).
> The requirement to check map is in `04-RESEARCH.md` section "Validation Architecture"; the plans `04.1-NN-PLAN.md` are authoritative for stage names, case ids and verify commands.

> **Evidence discipline.** Every green here is E0 repeatability. A raw-video hash is a verdict only paired with a literal shown to fail (ER-11). Manual-page literals are tagged MAN with their page label; no sprite entry is promoted to E1 documentary, so every sprite claim is a labelled assumption with its level (LED-VID-0011 R2, LED-VID-0012 R1). No withheld claim word is used.

## Sampling Rate

- **After every task commit:** the task's own narrow command (the `ds_runner --only ID` cases it touches and the narrowest stage). Plans 04.1-01 and 04.1-02 ran the full gate before every commit; plan 04.1-03 ran the narrow stages per task and the full set once at the end (gate cadence of 2026-11-12), because it changes no code and no golden.
- **After every plan:** `sh scripts/check`, `--selftest`, the audit range and the `gate-gcc` Linux part where C changed.
- **Before verify-work:** full suite, `dash scripts/check`, the second awk (the `mawk` and `gawk` Linux parts) and all six Linux parts.
- **Max feedback latency:** under 60 s for the per-task command.
